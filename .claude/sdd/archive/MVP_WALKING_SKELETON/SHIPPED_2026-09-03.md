Federation, no static keys. Live in `brasil2036-dev` (Cloud Run, `southamerica-east1`).

- API: `https://br2036-api-gzt6fzwoda-rj.a.run.app` — `/v1/metrics/{id}`, `/v1/provenance/{id}`, `/openapi.json`

## 6. Lessons learned

1. **Technical — never issue DML right after a BigQuery streaming insert.** `insert_rows_json` parks rows in a streaming buffer that blocks `UPDATE/DELETE/MERGE` for ~90 min, and the error only shows up at runtime against real BigQuery. Rewriting every control/gold write to `CREATE OR REPLACE TABLE ... AS SELECT` (pure DDL, immune to the buffer, and idempotent) removed a whole class of failure. Default to `CREATE OR REPLACE` for small rebuild-able tables; reserve streaming inserts for append-only high-volume paths.

2. **Process — build in GCP-independent slices first, then run against the cloud.** The connector, pt-BR parsing, data contract, SQL text and their tests needed no GCP and were fully verified with `uv run` locally; only `raw/bronze/registry/provenance/pipeline` and Terraform needed a project. Front-loading the verifiable part meant the "needs your billing account" blocker never stalled real progress.

3. **Technical — CI provisioning has two unavoidable chicken-and-egg points.** The WIF pool can't be created by a workflow that needs WIF to authenticate, and a Cloud Run service can't be created without a pre-existing image (and the web service also needs the api's post-deploy URL). Trying to force these into Terraform produced fragile multi-apply orchestration; the clean answer was a one-time `bootstrap.sh` + `gcloud run deploy` in CI, with Terraform keeping ownership of identity/IAM and an ADR (053) declaring the resulting public exposure so `terraform plan` stays a trustworthy diff for everything else.

4. **Process — an independent reviewer in an isolated context is worth it.** The author session cannot self-certify (ADR-034). A fresh read-only reviewer caught real gaps the author had rationalized away: services/WIF outside Terraform vs the SPEC's own MUST, a CODEOWNERS path that silently matched nothing, an over-broad `objectAdmin` on the immutable bucket. Cheap to run, and it turned "looks done" into a defensible PASS + a concrete debt ledger.

5. **Tools — pin the plugin assets or expect to improvise.** The SDD plugin's templates/contracts/`spec-linter` were not installed, so every phase document was composed from the skill's section list and the contract gates could not run. It worked, but a validated template + linter would have caught format drift for free. Vendor and pin the plugin (ADR-037 spirit) before relying on its gates.
