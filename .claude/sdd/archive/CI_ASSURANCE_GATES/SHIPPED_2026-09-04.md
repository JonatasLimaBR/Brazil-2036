## 1. Summary

Turns the CI pipeline from a soft advisory signal into an actual merge gate, closing achado #7
of the `MVP_WALKING_SKELETON` `/verify-spec` (AT11 PARTIAL) and realizing `SPEC-031` (ADR-054).
A path-filter-free umbrella workflow (`ci.yml`) runs a `changes` job on every PR/push to `main`,
feeds six conditional gates (`lint-typecheck-unit`, `web-check`, `terraform`, `integration`,
`spec-verify`, `secret-scan`), and aggregates them into a single always-resolving `ci-gate` —
the one required status check. `integration` now exercises the real ingestion pipeline against
an isolated, TTL'd BigQuery dataset (`citest_<run>_*`) instead of in-memory fakes, and
`spec_verify.py` gives `/verify-spec` a mechanical floor (files exist, OpenAPI paths present,
contract rules present, forbidden patterns absent, gates manifest complete) without replacing
the human reviewer.

- Branch protection on `main`: `required_status_checks == [ci-gate]`

## 6. Lessons learned

1. **Technical — a required status check must be one that always resolves.** Path-filtered check jobs can leave a required check stuck on "Expected — waiting" forever for PRs that don't touch that path — a real deadlock, not a hypothetical one (it's why achado #7 existed). The fix generalizes beyond CI: any gate condition tied to a required check needs a fallback path that reports pass/fail deterministically, never silence. `ci-gate`'s `if: always()` + explicit `needs.*.result` check is the reusable pattern.

2. **Technical — let the test own its own resource lifecycle, not the orchestrating workflow.** Autonomous Decision #2 moved `bq mk`/`bq rm` out of the YAML workflow and into the pytest fixture's `finally` block. This means the exact same lifecycle runs identically whether triggered from CI or a local `pytest -m integration` run, and there's one code path to debug instead of two (workflow shell script vs. test code) that could silently drift apart.

3. **Process — running the fake-vs-real integration test through the actual production connector (not a parallel test-only path) caught nothing new here but eliminates a whole class of future drift.** D6 added a `file://` branch to the real `DividaEstadosConnector.download()` instead of writing a `FixtureConnector`. Any future change to `download()` gets exercised by the integration test automatically; a parallel test connector would need to be kept in sync by hand.

4. **Process — an independent `/verify-spec` pass earns its cost even on infrastructure work.** The isolated reviewer found a real gap the build session had missed: `ci-gate`'s `needs` list didn't include `changes`, so if `changes` itself broke, every downstream gate reported `skipped` and `ci-gate` still went green — silently disabling the entire gate. That's exactly the failure mode this feature exists to prevent, and it was caught before merge, not after.

5. **Tools — SDD plugin assets (templates, contracts, `spec-lint`) are still not installed in this repo.** Both DEFINE and DESIGN documents needed to improvise the section list from the skill descriptions rather than a pinned template, same gap noted in the MVP_WALKING_SKELETON SHIPPED lesson #5. Not yet acted on across two shipped features — worth resolving directly if a third slice hits the same friction.
